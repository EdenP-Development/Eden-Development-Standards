2026-11-25. Extends the original provisional v0.1 audio direction in place. Sudoku Beta 3 is the reference pilot, not universal device certification. No distribution or final approval authorized. Spudacus remains the player-facing developer; EdenP Development is engineering infrastructure.

- Cozy Puzzle: Sudoku and Word Search. Preserve six owner-selected tracks, Warm Puzzle Time main theme, felt piano, acoustic guitar, restrained percussion, warm paperback nostalgia and low-distraction listening. See [versioned library](library/v0.1/README.md).

## Music Corner and preferences
Provide a clearly labeled Music Corner with background music toggle, current title, truthful preparing/playing/stopped/interrupted/unavailable state, previous/next, play/stop, volume and optional track list. Keep controls accessible (48dp minimum Android targets, screen-reader labels, large text and responsive portrait/landscape). Production has no private import controls. Bundle selected tracks offline; no runtime network, accounts or external service. No music or sound required for puzzle actions.
Recommended fresh defaults music on, puzzle sounds on, touch feedback on, independent music/effects volumes 50%. Preserve explicit existing choices, including off and zero volume; validate malformed values safely. Stable game-local track identity mapped to library ID; never migrate IDs merely for shared naming. Restore selected track, not exact timestamp; main theme first for new selection, other tracks shuffled and rotated in Sudoku pilot. Device-local audio settings distinct from portable progress backup. Do not expand backup scope silently.

## Playback lifecycle
One activity/root owner, not per-screen music instances. Silent skippable branding; start only after startup completion/skip and foreground readiness. No restart on normal screen navigation. Stop/release on pause/stop, disposal and backup/recovery lock. Foreground return may restart selected track if enabled and not interrupted. Request audio focus; interruption or error stops and requires explicit retry; no repeated focus requests. Deduplicate active same-track requests, ignore stale callbacks, use actual prepared/start status, clear state on stop, release player and focus. Handle missing files or unsupported devices gracefully. No background service or crossfade required. Android reference MediaPlayer with descriptor offset/length for bundled assets, asynchronous preparation and noCompress for M4A. Other platforms adapt behavior, not Android code wholesale.

## Sound effects and haptics
Six semantic puzzle cues in library v0.1: select, number, note, erase, undo, complete. Independent persistent Puzzle sounds toggle/volume, optional audition controls with clear labels. Load once per appropriate lifecycle, wait for successful load, bounded streams, release resources, fail harmlessly without blocking gameplay. Android pilot uses SoundPool descriptor-based WAV loading and synthesized PCM; do not synthesize per tap. Number and erase must be perceptually distinguishable on actual hardware. No correctness leaks or stacked reward cues. Completion only once per eligible same-round incomplete-to-complete transition; no replay from restored completed saves or duplicate network snapshots. Haptics are separate semantic feedback, independently optional, respect platform/system settings and accessibility; validate perceived strength on supported devices, not just invocation. No mandatory vibration permissions or new dependencies without review.

3. Android WAV byte equivalence to desktop exports or explicitly reviewed platform-specific revision.
4. Targeted physical regression: Final Piece intro, number/erase distinction, completion guard, focus interruptions, foreground/backup lock, independent toggles and volumes, silent splash, offline playback, rotation/large text/accessibility and physical multiplayer where supported.
