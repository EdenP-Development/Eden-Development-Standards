# EDT-07 v0.2 — Deterministic task reservations

Original dependency-free ES module. resolve({tick,previous,requests,releases}) returns version, tick, claims and outcomes. Tick is nonnegative safe integer, strictly increasing relative to previous snapshot; reset with previous=null. Trusted single authoritative simulation caller only. Requests use agent/task ASCII IDs (1–64 letters/digits/underscore/hyphen), priority 0..100 and positive integer duration in ticks. Releases use agent/task. One request per agent per batch, one active task per agent and one owner per task. Up to 4096 claims, requests and releases each.

At tick >= expires, claim expires. Process releases before requests; only matching owner release removes active claim. Unknown or foreign releases ignored. Valid current claim cannot be preempted. Requests sort by descending priority then ascending agent ID; same owner may renew without shortening expiry. Outcomes granted/renewed/task-busy/agent-busy/capacity. Claims sorted by task ID. No input mutation for ordinary plain-data snapshots. Caller must check task existence, eligibility, actor lifecycle and resource availability before reservation and execution; revoke invalid tasks via owner release. Not a distributed lock, authentication, resource inventory, scheduler, fairness guarantee or automatic world mutation. Lexicographic ties can starve agents; future aging policy requires separate version. No automatic coupling to v0.1 selector; adapter must map priorities and durations explicitly.
