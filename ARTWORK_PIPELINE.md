# Original artwork pipeline

Status: adopted procedure; Crossroads transfer and independent byte verification passed on 2026-11-24 (local time). Do not describe an unverified candidate as release-approved.

## 1. Generate and preserve
Use approved project style references and original generated artwork. Preserve source generation IDs, original images, processing recipe, asset IDs, dimensions, alpha requirements and license/provenance. Do not regenerate approved art merely because a chat ends. Keep source libraries separate from runtime assets. Never substitute code-drawn artwork silently.

## 2. Process and package
Extract sprites, remove unwanted backgrounds, preserve proportional scale and transparent gutters, and use stable filenames. Record SHA-256 of every PNG and the final ZIP before transfer. Include a manifest and compare against the project art contract. Keep private or sensitive content out of public repositories.

## 3. Transfer through Google Drive
Reported working method from Crossroads IDENTITY-17: upload the prepared binary archive to the authorized private Drive location, retrieve its original binary bytes using the connected Drive workflow, encode bytes as base64 exactly once, create a GitHub binary blob with encoding=base64, then create a tree based on the existing branch tree, create a commit with the current branch head as parent, and update the intended development ref without force. Do not change sharing permissions. Do not use a UTF-8 text-file writer for binary content. Record archive names, original hashes, blob IDs, commit and branch in the project handoff. Exact connector invocation details from the original session are not yet independently reconstructed.

## 4. Independent verification
Checkout the committed branch in CI and compare archive SHA-256 against the pre-transfer receipt (not against a hash generated from the newly retrieved bytes). Reject mismatches, duplicate/unsafe ZIP paths, unexpected files and excessive decompressed sizes. Validate individual file hashes, PNG dimensions, alpha and transparent gutters. Use project-specific import scripts and manifest/registry validation. CI artifacts alone are not a source commit; explicitly commit validated runtime assets or use a reproducible build-time import. Retain native fallbacks and package only used artwork.

## 5. Integration and acceptance
Review visual consistency, state bounds, scaling, contrast, actual game screenshots and real-device play. Preserve app identity, saves and signing policy. Run existing regression tests and signed APK verification. Separate transfer, byte verification, runtime integration, and owner visual approval statuses.

## 7. Large archive fallback and actual image formats — Sudoku Beta 3
Verified 2026-11-24 local: when a single 8.32 MB archive blob request failed, split the original ZIP into 14 raw binary parts, upload each as base64 Git blob, commit together on the intended development branch and concatenate in lexical order in read-only CI. Verify exact original ZIP SHA-256 before decoding, reject unsafe paths and size limits, compare every manifest hash and actual decoded image dimensions/mode. Do not assume filename extensions identify actual encodings: Sudoku's two promotional files labeled PNG were WebP; preserve original bytes and export corrected extensions. Do not regenerate artwork or relax checksum checks. The original ZIP hash authenticates the recovered archive against the pre-transfer receipt, not original generation bytes. Evidence: https://github.com/EdenP-Development/SudokuTogether/actions/runs/45543787474 (passed); transport commit https://github.com/EdenP-Development/SudokuTogether/commit/61c27feb7eeae9d552c9abc59579a2bebaa9f0a7. Keep native assets or reproducible build-time import; do not remove transport until durable verified replacement exists. Separate physical review from byte validation.

Successful individual habitat connector sequence recorded in Sudoku handoff: Drive upload_file(file_uri=original conversation file ID), get_file_metadata, fetch(url,download_raw_file=true,include_base64=true) for bounded legacy binary compatibility, pass returned b64_string directly to GitHub create_blob(encoding=base64), then tree/commit/compare-and-swap ref update. Never double-encode or print raw bytes. This sequence is project-reported; independent habitat pre-transfer hash checks remain pending.

## 8. Chat continuity and proportional recovery — 2026-11-28
Owner direction: preserve real files as work proceeds; missing replaceable promotional art must not stall playable development. At each accepted or useful asset checkpoint, transfer the original binary and final export to an authorized durable private location, record stable locator, size, format and checksum, and verify retrieval against the original receipt. Record template/source and processing recipe alongside outputs. Use explicit states: generated, transferred, byte-verified, visually accepted, integrated/published. A chat link, generation ID, textual description or expiring artifact alone is not a backup. If transfer is unavailable, mark the item unarchived immediately and provide a downloadable original when possible; do not claim preservation. Prioritize irreplaceable source, signing material (separate secure storage), saves and approved masters over disposable iterations. Keep recovery time proportional to asset value; defer or regenerate replaceable promotional art rather than blocking gameplay. Before switching chats, update project handoff with exact archive status and next actionable milestone. No private assets in this public hub.
